# TASK-BACKFILL-VOTES-001: 議案個別賛否（memberVotes）バックフィル 専用タスク定義

生成日: 2026-08-24
親: UNR-031（議案個別賛否バックフィルの構造的ギャップ）
前提調査: Phase91（2026-08-23、パイロット調査。`reports/phase90-91-96-parent-led-findings.md`参照）

## 1. 背景（要約）

`src/data/billVotes.json`（全1,177件）のうち、議案自体の採決結果（可決・否決等）は1,177/1,177件で出典確認済みだが、
議員個人別の賛否内訳（`memberVotes`）が実データとして入っているのは**2件のみ**。Phase91のパイロット調査で、
サイトが既に一次資料として使用中の「議案審査等結果」PDF（各会期の審査結果一覧）には議案番号・件名・審議結果・
議決日のみが収録され、個別議員の賛否は一切含まれないことを確認済み。したがって1,177件全件の網羅的取得は
現実的でなく、無制限のバックフィルは行わない方針とする。

## 2. 分類方法（今回、既存フィールドの機械集計のみで実施。新規の一次資料調査は行っていない）

`billVotes.json`が既に保持する`voteMethod`（採決方法）・`individualVoteDisclosureStatus`・`memberVotes`の
3フィールドを機械的に突合し、A〜Fへ分類した。

| 分類 | 定義 | 該当voteMethod | 件数 |
|---|---|---|---|
| A | 個別賛否一次資料あり（`memberVotes`に実データあり） | 記名投票 | **2** |
| B | 採決結果のみあり（簡易採決・全会一致＝そもそも個人別集計を伴わない採決方式のため、原理的に個人別記録が存在しない） | 簡易採決／全会一致 | **1,095**（簡易採決1,093＋全会一致2） |
| C | 会議録から復元可能かもしれない（起立採決＝挙手・起立の多数決で、会議録本文に反対者名が記載されている場合がある。個別に会議録原文を精読しないと有無が判明しない） | 起立多数／起立少数 | **52** |
| D | PDF画像解析が必要 | （該当を機械識別できるフィールドなし。C調査の過程で判明した場合のみ再分類） | 0（未確定） |
| E | オンライン資料なし | 採決なし（議案取下げ等、そもそも採決が発生していない） | 4 |
| F | 未確認（直近会期でvoteMethod未設定＝通常のデータ反映パイプライン待ち。バックフィル対象ではない） | (未設定、令和8年5月臨時会・6月定例会) | 24 |
| **合計** | | | **1,177** |

注：individualVoteDisclosureStatusの内訳（`disclosed`=2／`unconfirmed`=654／`notDisclosed`=521）は上記A〜Fと
軸が異なる（「公開されているか」の別集計）。`notDisclosed`（521件）は「未収集」ではなく「公式資料上そもそも
個人別記録が存在しないことを確認済み」の状態で、上表のB（簡易採決・全会一致）と一部重なるが完全一致はしない
（`notDisclosed`の判定基準はvoteMethodと独立して個別レコードごとに記録された過去の確認結果のため）。今回は
両フィールドの整合性の突合までは行っていない（次フェーズの課題）。

## 3. 実質的なバックフィル対象（推定）

B（1,095件）・E（4件）・F（24件、パイプライン待ちで自然解消見込み）は、原理的に個人別記録が存在しないか
未確認状態が自然に解消される見込みのため、**専用バックフィルの対象としない**。

## 4. 次の一歩（本タスクでは未実施。今後の専用フェーズへの引き継ぎ）

1. 上記52件について、延岡市議会会議録検索システム（kensakusystem.jp/nobeoka）の該当会期・該当議案の
   討論・採決部分を個別に精読し、起立者・反対者の氏名が会議録原文に記載されているかを確認する。
   記載がある議案のみ`memberVotes`へ構造化する（記載がなければCから確定的にBへ再分類する）。
2. パイロット範囲として、直近5会期（令和7年3月・9月、令和8年3月＝合計6件）から着手することを推奨する
   （Phase91が既に検証したとおり、審査結果PDFではなく会議録本文の取得・精読が必須のため、1件あたりの
   調査コストが高い。無制限の同時並行取得は行わない）。
3. schema自体（billVotes.jsonの`memberVotes`配列：議員ID・賛成/反対/退席/欠席/棄権・採決方法・sourceRef）は
   既存の2件（2019-09-gian-47、2023-07-extraordinary-01-gian-9）で実運用実績があるため、新規スキーマ設計は
   不要。既存スキーマをそのまま利用する。
4. individualVoteDisclosureStatusとvoteMethodの整合性突合（上記2章の注記）を、バックフィル着手前に
   別途実施することを推奨する。

## 5. 品質方針の遵守事項

- 起立採決52件のうち、会議録原文で反対者名が確認できなかった議案を「未収集」のまま放置せず、
  `notDisclosed`（原理的に個人別記録が存在しないことを確認済み）として明示的に記録すること。
- 会議録原文に記載がある場合でも、記載内容をそのまま転記し、記載のない議員の賛否を出席者名簿等から
  推測で補完しないこと。
