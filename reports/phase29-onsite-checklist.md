# 回答登録手順・現物確認手順（1970年代 市長選挙・特別職）

作成日：2026-08-21（Phase29）／Phase30で「回答受領後の登録ルール」を追記

## 0. 回答受領後の登録ルール（最優先で確認すること）

外部機関から回答（メール・電話・書面）を受け取ったら、以下の手順で処理する。

1. **回答メールそのものだけでconfirmed_primaryへ昇格させない。** 回答メールは「原本のどこに何が書いてあるか」を教えてもらうための手がかりであり、それ自体は一次資料そのものではない。
2. 回答で示された資料名・議案番号・会議録の年月日・選挙録等の情報をもとに、**可能な限り原資料を直接確認する**（NDL・現地図書館での閲覧、複写の取り寄せ等）。
3. 原資料を直接確認できた場合に限り、既存のconfidenceルール（`confirmed_primary`／`confirmed_official`／`secondary_only`／`unconfirmed`・`disputed`）に従って昇格を検討する。
4. 原資料を直接確認できない場合（回答のみで現物入手に至らない場合）は、回答内容を`reports/phase21-inquiry-tracker.json`の該当レコードの`confirmedFacts`に記録し、データ本体（`src/data/*.json`）へは反映しない。回答内容が信頼できる公的機関からの正式な情報である場合でも、それだけでは"verified"の一次資料と同列には扱わない。
5. 「回答なし」「記録が残っていない」という回答も、正式な調査結果として`no_record`ステータスで記録する（未回答のまま放置しない）。
6. 現地閲覧が必要と判明した場合は`onsite_required`ステータスへ変更し、下記「現物調査チェックリスト」を用いて記録する。

## 1. 現物調査チェックリスト

現物資料を閲覧する際に、その場で記録すべき項目のチェックリスト。1件の資料・1件の事実ごとに1シートを埋める運用を想定する。空欄のまま持ち帰った場合、後日の再訪が必要になるため、閲覧時にできる限り埋めること。

## 基本情報（資料そのものについて）

- [ ] 資料名（正式な書名。表紙・奥付で確認）
- [ ] 編者／著者
- [ ] 発行者
- [ ] 発行年（西暦・和暦の両方）
- [ ] 巻号（上巻／下巻／第◯号等）
- [ ] 所蔵機関
- [ ] 請求記号
- [ ] 配架場所（郷土資料室等）
- [ ] 複写可否（可・不可・一部可）
- [ ] 複写した場合の管理番号／撮影番号

## 該当箇所の特定

- [ ] ページ番号（または コマ番号／会期回次）
- [ ] 表題・見出し（章・節・議案名等）
- [ ] 該当箇所の写真撮影番号（複数枚に分かれる場合は全て記録）

## 人物情報（1名につき1セット）

- [ ] 人物名（フルネーム、可能であれば読み仮名も）
- [ ] 役職（助役／収入役／議長／副議長／教育長／候補者 等。当時の正式名称のまま記録し、現代名称へ読み替えない）
- [ ] 就任日（議決日・選出日・当選日等、日付の種類を明記）
- [ ] 退任日（辞職日・任期満了日・後任選任日等、日付の種類を明記）
- [ ] 前任者名（分かる場合）
- [ ] 後任者名（分かる場合）
- [ ] 再任の有無（再任の場合、通算の在任回数）

## 選挙情報（1回の選挙につき1セット）

- [ ] 選挙日（投票日）
- [ ] 告示日（分かる場合）
- [ ] 候補者全員の氏名
- [ ] 候補者別の得票数
- [ ] 有効投票数・無効投票数
- [ ] 投票者数
- [ ] 有権者数
- [ ] 投票率
- [ ] 無投票か否か
- [ ] 当選者

## sourceRef候補（データ登録用）

- [ ] sourceUrl（デジタル資料の場合。現物のみの場合は「現地閲覧」等と記載）
- [ ] sourceTitle（正式な資料名＋巻号＋発行年＋該当ページ／コマ）
- [ ] sourceOrganization（発行者）
- [ ] accessedAt（閲覧日）
- [ ] extractionMethod（"onsite_manual"等）
- [ ] verificationStatus候補（原本を直接確認できた場合は"verified"の候補になり得るが、既存のconfidenceルールに従い、登録時にプロジェクト側で最終判断する）

## 備考欄

- [ ] 判読に不安が残る箇所（誤読の可能性がある文字・数字）
- [ ] 同姓同名等、人物同定に注意が必要な点
- [ ] 既存データ（本サイト）との矛盾点（あれば具体的に記載）
- [ ] 次回の追加確認が必要な箇所

---

## 運用ルール

- **原本内容を直接確認した場合のみ**、既存のconfidenceルール（confirmed_primary等）に従ってデータ登録を検討する。「この資料に載っている可能性が高い」という推測段階では登録しない。
- 複数の資料で矛盾する記載を発見した場合は、どちらか一方を自動的に正しいとせず、両方を記録した上でプロジェクト側の判断を仰ぐ（`disputed`として記録する）。
- 撮影・複写したページは、後で本サイトのデータ登録作業をする際に参照できるよう、ファイル名に資料名・ページ番号を含める等、分かりやすく整理すること。
