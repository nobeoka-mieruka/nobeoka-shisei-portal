# Phase123（旧称Phase65）市民向けUI・可視化強化 実施報告

対象：延岡市政見える化ポータル（非公式）。React + TypeScript + Vite + Tailwind CSS。
既存データ・既存ページを壊さないことを最優先し、既存コンポーネント（StatCard, SectionCard, BarList等）を再利用した。

## A. トップページ整理（実装済み）

`src/pages/HomePage.tsx` は、Phase94以降の作り込みにより既に「①検索ヒーロー→②サイト概要→③目的から探す（4カテゴリカード）→信頼性導線→市政データ概要→最近の更新→データ整備状況→議員を探す→詳細絞り込み（`<details>`で折りたたみ）→アクセス統計」という構造になっており、詳細な絞り込みUIは`<details>`で畳まれ縦の長さは抑えられていた。

今回は、ユーザー指示にあった「議員を調べる／一般質問を調べる／議案を見る／市長を調べる／財政を見る／市役所の相談先を見る」の6導線を、ヒーロー検索の直下・最上部に**追加**した（既存の「目的から探す」4カードは変更・削除なし）。

- 追加：ヒーロー直下の「よく使われるページへのショートカット」`<nav>`（`aria-label`付き、6ボタン、375pxで3列×2行→640px以上で6列）
- 各ボタンは`min-h-[76px]`のタップ領域、アイコン＋ラベルの2行構成、`focus-visible`のアウトライン、色だけに依存しない（アイコン＋テキスト併記）
- 既存リンク先（`/people?type=member`、`/questions`、`/bills/votes`、`/mayor`、`/finance`、`/city-guide`）はすべて既存ページで、新規ルートは追加していない

## B. 市政総合ダッシュボード（部分実装：既存ダッシュボードへのセクション追加）

`src/pages/DashboardPage.tsx`（議会構成・一般質問・議案の統計が中心）に、`src/data/financeDashboard.json`（`/finance`ページと同一データソース、二重管理なし）を再利用した新セクション「延岡市の基礎データ（人口・財政）」を追加した。

表示項目（すべて公式資料に基づく既存データ、新規データ捏造なし）：
- 人口（最新基準日時点）
- 一般会計総額（6月補正後）
- 市税（歳入・6月補正後）
- 基金全体（残高）
- 市債（歳入・当年度発行予定額。年度末残高＝ストックではない旨を明記）
- 経常収支比率（`financialIndicators`が無い場合は「確認中」表示、0扱いにしない）

**未実装・意図的に見送った項目**：高齢化率、出生数、死亡数、転入者数、転出者数。
`src/data/`配下を`nobeokaCensusPopulation.json`・`archiveFiscalYears.json`・`financeDashboard.json`含め全体検索したが、これらの指標に該当するフィールドは存在しなかった。CLAUDE.mdの「推測、架空データ、根拠のない順位、独自採点を掲載しない」「欠損値を推定で補完しない」に従い、フィールドを捏造して0や空欄を表示することはせず、セクション末尾に「高齢化率・出生数・死亡数・転入者数・転出者数は、当サイトが確認できた公式資料に該当データが無いため、現時点では未収録です（0件という意味ではありません）」という注記のみを追加した。公式統計（国勢調査の年齢別人口、住民基本台帳の自然動態・社会動態等）を新たに収集・登録する作業は今回のスコープ外（別タスクとして提案）。

議員数・一般質問件数・議案件数は、DashboardPage上部の既存StatCardで既に表示されており、重複実装しなかった。

## C. 市政タイムマシン構想（大部分が既に実装済み・今回は現状確認とギャップ分析）

`git log`で確認したところ、`/timeline`（`TimelinePage.tsx`）と`/timeline/:year`（`TimelineYearPage.tsx`）は既存の過去フェーズで実装済みであり、ユーザーが依頼したC.の要件（年度を選択すると当時の市長・議員・人口・一般会計・基金・市債・主な議案・一般質問・主な政策を横断表示）を**既に満たしている**ことを確認した。重複実装を避けるため、今回はコード変更を行わず、設計・現状の検証結果のみ以下に記録する。

### 1. データモデル（既存、`src/types/historicalArchive.ts` 等）
- `ArchiveMayor` / `ArchiveMayorTerm`：歴代市長・任期
- `ArchiveMemberProfile` / `ArchiveMemberTerm`：歴代議員・在籍期間
- `ArchiveFiscalYear`：年度ごとの`population`（人口・世帯数）、`budget`（一般会計）、`debt`（市債発行額・残高）、`fund`（基金）、`financialIndicators`（経常収支比率等）を束ねるルートオブジェクト
- `GeneralQuestionItem`：一般質問（既存）
- `ArchiveCouncilDocument`：議案・条例・請願・陳情（既存）
- `ArchivePolicy`：政策・公約アーカイブ（既存）
- 年度別集約は`src/lib/archiveTimeline.ts`の`groupEventsByFiscalYear`等が担当し、各データソースを横断イベント配列に正規化している。

### 2. ルーティング（既存、重複なし）
- `/timeline`：全期間の年度別イベント一覧（カテゴリ絞り込み可）
- `/timeline/:year`：単年度の横断表示（市長任期・議員在籍・財政人口指標・一般質問・議案・政策）
ユーザー案の「`/timeline/:year`」は既存の`TimelineYearPage.tsx`とルートが完全一致するため、新設せず既存実装をそのまま活用する方針で問題ないことを確認した。

### 3. UI（既存実装を確認）
`TimelineYearPage.tsx`は`SectionCard`を年度内カテゴリごとに積む構成（市長任期／議員在籍／財政・人口データ／一般質問／議案・条例・請願・陳情／政策／出典）で、既存共通コンポーネント（`CompareTable`, `CompareSourceNotice`, `LastUpdated`等）を再利用しており、新規に大きなライブラリは使っていない。データが無い年度は「確認できたデータはまだありません」と表示し0とは区別している。

### 4. 対応可能年度数（実データ集計、`archiveFiscalYears.json`）
- 登録年度レンジ：1933年度〜2026年度（70年度分のレコードが存在）
- うち人口データあり：26年度
- うち一般会計予算データあり：5年度
- うち市債データあり：38年度
- うち基金データあり：26年度
- うち財政指標（経常収支比率等）データあり：0年度（`financialIndicators`は現状すべて未登録）

### 5. 欠損データ一覧
- `archiveFiscalYears.json`の登録済み年度範囲（1933〜2026）内で欠番：1934-1948（一部）、1951-1953、1959、1983-1987（`npm run validate:data`のWARNで機械的に検出済み、既存の欠損）
- `financialIndicators`（経常収支比率・実質公債費比率等）は`archiveFiscalYears.json`側では全年度未登録（`/finance`単年度ページの`financeDashboard.json`側にのみ最新年度分が存在）
- `archiveMayorTerms.json`に13件の任期空白期間（validate-dataのWARNで検出済み、既存の既知課題）

これらはいずれも一次資料が未確認のための既存の欠損であり、今回のPhase123では新規の推測補完は行っていない。

## モバイル表示上の懸念点

- 追加したクイックリンクは`grid-cols-3 sm:grid-cols-6`・`min-h-[76px]`で構成しており、375px幅でも1項目あたり約110px幅を確保できるため横スクロールは発生しない（`overflow-x`指定は追加していない＝固定幅による横あふれなし）。
- 「市役所の相談先を見る」等、ラベルが長い項目は375px幅の3列表示で2〜3行に折り返される見込みだが、`leading-tight`指定済みで縦書きや文字化けの心配はない。実機ブラウザでの確認は本環境では実施できていないため、公開後に実機（375/390/768/1280px）での見た目を確認することを推奨する。
- ダッシュボードの新セクションは既存の`grid grid-cols-2 sm:grid-cols-3`パターン（`StatCard`）をそのまま踏襲しており、他セクションと表示崩れの一貫性リスクは低い。
