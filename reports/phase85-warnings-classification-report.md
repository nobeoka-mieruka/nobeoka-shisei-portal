## 4. councilSpeechSummaries.json（13件・分類I）

`scripts/validate-data.mjs` 2780-2782行目のチェックロジックを実際に読んで検証した。

```js
if (q.questionApproach && !RECOMMENDED_QUESTION_APPROACHES.has(q.questionApproach)) {
  warn(speechTag, `questionApproachが推奨語彙にありません（誤りではないが確認推奨）: ${q.questionApproach}`);
}
```

`RECOMMENDED_QUESTION_APPROACHES`（同2619-2638行目）は18語彙の固定セット（現状確認、制度内容の確認、予算・数値の確認、実施時期の確認、今後の方針の確認、改善提案、事業導入の提案、対応の要望、課題の指摘、再質問による追加確認、拡充の要望、検証の要望、現状認識の確認、現状の確認、所信の確認、進捗の確認、所感の確認、検証・所見確認）。このセットに含まれない`questionApproach`値は、たとえ内容が正しくても機械的に`warn()`される設計であり、`err()`（エラー）ではなく明示的に「誤りではないが確認推奨」という軟性警告になっている。

13件全てについて`src/data/councilSpeechSummaries.json`の該当レコードを実際に読み、`summaryStatus`と`questionSummary`本文を確認した結果、対象13件は全て`summaryStatus: "verified"`（会議録に基づき確認済み）であり、questionApproach値と質問内容に矛盾・誤りは見られなかった。警告が発生する根本原因は**validate-data.mjs側の固定語彙リストが実際に使われている正当な自由記述表現を網羅しきれていないこと**であり、データ側の問題ではない。よって分類Iと判定した（Iの判定は妥当）。

いずれもデータの誤りを修正するものではなく、語彙整備の性質のものであるため、既存データを壊さない観点からはPhase88で慎重に判断すべき。
