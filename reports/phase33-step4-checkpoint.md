## 一般質問バックフィルの状態

`src/data/questionCollectionStatus.json`（2026-08-05生成）を確認した。現任期（令和5年5月〜）の対象定例会13会期中、会議録未取得は1会期（令和8年6月定例会）のみで、これは`blockedTaskClassification.json`で既に`WAITING_EXTERNAL`として追跡されている（会議録がまだ公開されていないだけで、DB化作業自体の遅れではない）。旧任期（令和元年6月〜令和5年3月）分も既存の確認済み件数（`questionStats.confirmedCount`）に含まれ、収集済みであることを確認した。

**結論：現行スコープ（現任期＋旧任期＝令和元年6月〜）において「会議録は存在するがDB化されていない」という意味でのバックログは実質0件だった。** 唯一の未収録（令和8年6月定例会）は外部要因（会議録未公開）であり、自動再チェック機構（GitHub Actions日次巡回）により会議録公開時に自動反映される設計になっている。

## 大量バックフィル候補：2000〜2019年（旧々任期以前）の一般質問

延岡市議会会議録検索システムは2000年5月以降を収録している（既存docs/nobeoka-minutes-fetch-investigation.md等で確認済み）。しかし、現行のcouncilSpeechSummaries.jsonは「現任期＋旧任期（令和元年6月〜）」に意図的にスコープを絞っており、2000年〜2019年（平成12年〜令和元年）の一般質問は、会議録自体はオンラインに存在するが、当サイトへのDB化はまだ行われていない。

### TASK定義（TASK-BACKFILL-001）

| 項目 | 内容 |
|---|---|
| 対象期間 | 2000年5月〜2019年5月（会議録検索システム収録開始〜旧任期開始前） |
| 推定件数 | 現任期＋旧任期（約6.5年分）で398件収録済みであることから比例推計すると、約19年分で概算1,100〜1,200件程度と推定される（**推定値であり確定値ではない**。実際の登録議員数・質問頻度の変動により誤差が大きい） |
| データソース | 延岡市議会会議録検索システム（kensakusystem.jp/nobeoka） |
| 取得方法 | 既存のscripts/fetch-nobeoka-minutes*.mjs・scripts/generate-speech-summary-scaffold.mjs等、現行パイプラインの対象期間を拡張して再利用する想定（新規スクリプトの必要性は要検討） |
| parser利用可否 | 既存parserが2000年以降の会議録フォーマットに対応可能かは未検証。フォーマット変更（特に2000年代前半）の可能性があり、事前のサンプル検証が必要 |
| rate limit | 既存のfetch系スクリプトのrate limit設定を踏襲（会議録検索システムへの過度なアクセスを避ける） |
| checkpoint方法 | 会期単位でのチェックポイント（既存の`speeches:list-pending`等のレビューフロー踏襲） |
| validate方法 | 既存の`npm run validate:data`に加え、旧任期データ登録時と同様の人手レビュー（`speeches:review`）を経る |

**今回はこのTASKの定義のみを行い、実際の取得・バックフィルは実行していない**（数千件規模の一括取得を無制限に行わない、という指示に従った）。
