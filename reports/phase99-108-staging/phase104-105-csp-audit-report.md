## Phase104: csp-49（高島安三郎）複数期一括レコードの検討

### 結論：分割しない

既存の csp-46（後藤梅雄、助役14・15代）・csp-47（高橋重行、収入役12・13代）と同じ「1レコード＋termNoteで複数期を記述」パターンをそのまま踏襲するのが妥当と判断した。理由：

- csp-49の7代・8代・9代はいずれも同一人物・同一役職（収入役）の連続する任期であり、既存パターンの適用条件を満たす。
- 分割すると新規ID採番・sourceRefsの複製が必要になるが、sourceRefsは元々「延岡市史 上巻コマ126の同一覧表」という単一の一次資料であり、分割しても情報量は増えない。
- 8代は昭和34年/35年の表記ゆれ、9代は日付自体未確認。タスク指示の「8代・9代は月精度以下のままなら分割を保留してよい」に該当する。

### 別件：appointedDateの反映漏れ（新規調査ではない）

termNoteには7代の開始日1951-01-28・終了日1955-02-18が日精度で既に記載され「複数回一致したためある程度の確度がある」と明記されているが、appointedDate/retiredDateは共にnullのまま。Phase92でcsp-47に対して行った「termNoteにある日精度日付を構造化フィールドへ反映する」修正と同種のパターンである。

- **appointedDate**: `1951-01-28` への反映を提案（7代開始日、確度が高い）。
- **retiredDate**: `null`のまま据え置くことを提案。1955-02-18は7代→8代への交代日であり、本人はこの日に収入役を退任していない（8代終了時に「助役就任（転任）」との記載があり、実際の退任は8代終了時点＝表記ゆれのある昭和34/35年5月18日）。ここにretiredDateを入れると「1955年に退任した」という誤った事実を作ってしまうため入れるべきではない。

ただし、csp-49のtermNote末尾には編集者自身による「appointedDate／retiredDateへの反映は昭和34/35年の表記ゆれが解消してから行う」という申し送りがある。今回の提案（appointedDateのみ先行反映）はこの申し送りと部分的に矛盾するため、実施するかどうかは親エージェントの判断に委ねる。

## Phase105: csp-56（柳田喜継）・csp-57（三樹博）完全性監査

### csp-56（柳田喜継）

| 項目 | 評価 |
|---|---|
| 氏名表記 | 会議録・civicTimelineEvents（civic-176/177）と一致、揺れなし |
| appointedDate=null | 妥当（初回就任1991年の日付が未確認のため） |
| retiredDate=2006-02-03 | 後任csp-35の会議録内での言及に基づく（Level2相当。本人の退職議案そのものではない） |
| relatedLinks | `/timeline/2003`・`/city-officials` とも有効なルート |
| 重複登録 | なし |
| 前任・後任接続 | csp-35（杉本隆晴）と正しく接続。退任〜後任就任まで25日の空白は手続き上自然（矛盾ではない） |

**問題点（軽微）**: termNoteの「平成15年（2003年）2月13日、…で4期目の再任議決を受けた。」という文が、議決日（1月28日）と任期開始日（2月13日）を混同しているように読める。sourceRefsのラベルおよびcivic-176本文では議決は1月28日、2月13日は任期満了（＝新任期開始）日。修正案：「平成15年第26回臨時会（2003年1月28日、議案第74号）で、同年2月13日の任期満了に伴う4期目の再任議決を受けた。」への書き換えを提案。

### csp-57（三樹博）

| 項目 | 評価 |
|---|---|
| appointedDate=1983-02-10 | 日精度、一次資料に基づき妥当 |
| retiredDate=null | 妥当（同一覧表の対象範囲では確認できず、推測補完なし） |
| relatedLinks | `/city-officials` は有効なルート |
| 重複登録 | なし（csp-46「後藤梅雄」とは別人） |
| csp-46との9日間重複 | 原本自体の不整合として両レコードのtermNoteに明記済み、unconfirmed扱い。推測で解消していない＝適切 |

**問題点（中）**: `name: "（後藤）三樹博"` という括弧表記は、citySpecialPosts.json全57件中この1件のみに使われている独自表記。notesは「既存のcsp-54（姓のみ確定の助役レコード）と同様の表記方針とした」と説明するが、実際にはcsp-54は不確定な部分（下の名）を**省略**する方式（`name: "佐藤"`、括弧なし）であり、csp-57は不確定な部分（姓）を**括弧付きで残す**方式で、両者は不確定要素の扱いが逆になっている。「同様の表記方針」という記述は不正確。

修正案（いずれか）：
- A案：csp-54との整合を優先し `name: "三樹博"` のみとし、姓の手がかりはtermNote側でのみ説明する。
- B案：括弧表記を維持する場合、notesの「csp-54と同様の表記方針とした」を削除し、実態（csp-54とは異なる扱い）に即した説明へ修正する。

### 検索インデックス（searchIndex.json）

`scripts/generate-search-index.mjs` を確認した結果、**citySpecialPosts.jsonの個別レコード（csp-1〜csp-57すべて）は検索インデックス生成の対象になっていない**。member/mayor/bill/question/committee/election等は個別索引化されているが、citySpecialPosts用のセクションが存在せず、索引化されているのは固定の1件（`page-city-officials`、キーワードは役職名のみで個人名は含まない）だけである。

このため「柳田喜継」「三樹博」「高島安三郎」等の氏名でサイト内検索してもヒットしない。ただし**これはcsp-56/csp-57固有の問題ではなく、citySpecialPosts.json全体（57件すべて）に共通する既存の設計上の欠落**であり、今回の2レコード追加によって新たに生まれた問題ではない。改善するには `generate-search-index.mjs` に新セクションを追加する必要があり、`citySpecialPosts.json` 自体の編集では対応できない（スコープ外として記録のみ）。

### CityOfficialsPage.tsx の表示ロジック

`src/pages/CityOfficialsPage.tsx` を確認した。`formerPosts`（status==='former'）は配列の元の並び順（id昇順）のままフラット表示され、役職や年代でのグループ化・ソートは行われていない。csp-56・csp-57は表示自体は正しく行われるが、id番号が大きいため、関連の深いcsp-46・csp-47・csp-49（同じ助役／収入役、年代的にも近い）から画面上離れた末尾に表示され、前任・後任関係が視覚的にわかりにくい。技術的な不具合ではなく、歴代レコードが増えてきた現在のUXの改善余地として記録するに留める（`/city-officials`ルート自体はApp.tsxに存在し有効）。
