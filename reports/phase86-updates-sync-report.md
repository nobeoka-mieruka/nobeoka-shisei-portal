# 更新履歴（updateHistory.json）同期状況の調査レポート

作成日: 2026-08-23

## 調査の目的

`src/data/updateHistory.json`（市民向け更新履歴、現在109件）に記録されていない、
市民が実際にサイト上で確認できる変更点がないかを、直近のコミット履歴と突き合わせて調査した。
あわせて `/data-status` ページの表示値の整合性、更新履歴の並び順・日付形式も確認した。

**このレポート自体には、updateHistory.jsonへの追記・修正は一切行っていない。候補の洗い出しのみ。**

## 調査方法

1. `src/data/updateHistory.json` に最新エントリ（u97, 日付2026-08-17）を追加したコミット（`6edfbab`）を特定。
2. `git diff 6edfbab..HEAD -- src/data src/pages src/components` で、それ以降131コミット分の変更ファイルを洗い出し。
3. 各データファイル（`archiveMayors.json`、`archiveFiscalYears.json`、`civicTimelineEvents.json` 等）が
   実際にどの `src/pages` / `src/components` から参照されているかを grep で特定し、市民が閲覧できる
   ページに反映される変更かどうかを判定。
4. `updateHistory.json` を全件ダンプし直したところ、実は `u98`〜`u108`（日付2026-08-22・2026-08-23）が
   **既に追加済み**であることが判明（配列の末尾に追記されている）。この11件の内容を精読し、
   まだカバーされていない変更点だけを候補として抽出した。
5. `/data-status` ページ（`src/pages/DataStatusPage.tsx`）を全文読み込み、表示値の算出ロジックを確認。
6. `updateHistory.json` の日付ソート順・日付形式を機械的にチェックし、`/updates` ページ
   （`src/pages/UpdatesPage.tsx`）の表示ロジックと突き合わせて実際の画面表示への影響を確認。

## 主な発見: 更新履歴は思ったより最新化されていた

調査の過程で、直近の統合コミット（`d42d18f`・`4d53801`）が既に `u98`〜`u108` の11件を
`updateHistory.json` へ追記していたことが分かった。これにより、助役・収入役の記録拡充、
財政データの一部年度追加、請願・陳情アーカイブ26件、教育長就任日、元議員プロフィール補強、
一般質問データベースの2000〜2019年拡大、サイト内検索の選挙結果表示改善などは、
**既に更新履歴に反映済み**であることを確認した。

そのため、今回の候補は「既存の109件に本当に抜けている部分」に絞り込んだ。

## `/data-status` ページの表示値ズレ

`src/pages/DataStatusPage.tsx` の各件数（歴代市長○名、財政○年度分、議案○件…）は、
すべて `src/data` 配下の各JSONファイルを都度importしてその場で再計算しているため、
**件数自体は常に最新のデータと一致しており、ズレは見つからなかった**。

ただし1点、ページ最下部の「この集計の対象データ確認日（最新値）」という表示（`LastUpdated`
コンポーネントの `dataAsOf`）だけが、次のように **固定文字列でハードコードされている**ことを発見した。

```tsx
// src/pages/DataStatusPage.tsx 1065行目
<LastUpdated className="mt-4" dataAsOfLabel="この集計の対象データ確認日（最新値）" dataAsOf="2026年8月5日" />
```

他の同種ページ（`CommitteesPage.tsx`、`HistoryPage.tsx`、`MayorsPage.tsx`、`PoliticalFundsPage.tsx`等）は
すべて `dataAsOf={formatJapaneseDate(latestVerifiedAt)}` のようにデータから動的に算出しており、
`DataStatusPage.tsx` だけが例外的に固定値になっている。対象データは2026-08-23時点まで
継続的に更新され続けているため、この表示だけが実態（8月5日よりかなり後）と乖離している。
**このページ自体の修正は本タスクの範囲外のため行っていない**（`phase86-updates-sync-findings.json`の
`dataStatusPageMismatches` に記録のみ）。

## 更新履歴の並び順・日付形式

- 日付形式（`YYYY-MM-DD`）は109件全てで統一されており、フォーマットの不整合はなかった。
- `updateHistory.json` の生データ配列は、`u97`（index 0）から `u1`（index 97）までは正しく
  日付降順だが、その後に追加された `u98`〜`u108`（日付は全体最新の2026-08-22・23）が
  配列の末尾（`u1` より後）に追記されており、生データとしては降順になっていない。
- ただし `/updates` ページ（`UpdatesPage.tsx`）は `sortUpdateHistoryByDateDesc()`
  （日付文字列によるstableソート）を経由して表示しているため、**実際の画面表示は正しく
  新しい順になっており、市民から見える範囲への影響はない**。JSONファイル自体を
  日付降順に並べ直すことは、将来の可読性・保守性のための任意の改善提案として記録するに留める。
