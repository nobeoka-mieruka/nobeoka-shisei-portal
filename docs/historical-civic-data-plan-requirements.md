## 要件原文

以下、ユーザーが提示した要件を一字一句そのまま記載する。

### 基本方針

次の情報を、公式資料で確認できる範囲から追加してください。

1. 過去の市議会議員
2. 過去の延岡市長
3. 過去の副市長・教育長等
4. 歴代議会構成
5. 歴代市長の政策・公約・主要事業
6. 議員の政策・一般質問テーマ
7. 市債残高の推移
8. 基金残高の推移
9. 一般会計当初予算・最終予算・決算規模
10. 歳入・歳出の推移
11. 人口・世帯数等の基礎指標
12. 主要事業費の推移
13. 財政指標の推移
14. 市長・議員・会派・財政の関係を年代別に確認できる機能

公式資料で確認できない内容は、推測で登録しないでください。
「確認できない」「資料未発見」「公開範囲外」を明確に区別してください。

### 過去の議員データ

現職議員と過去の議員を同じ人物データ基盤で管理しつつ、現在の表示対象を区別できる
構造にしてください。

推奨構造：

```
members
- id
- slug
- name
- nameKana
- alternateNames
- status
- currentMember
- firstElectedDate
- termStart
- termEnd
- termCount
- retirementReason
- partyOrAffiliation
- faction
- committees
- profileUrl
- sourceUrls
- lastVerifiedAt
```

status例：current / former / resigned / lostOffice / deceased / termCompleted / unknown

retirementReason例：任期満了 / 辞職 / 失職 / 市長選挙立候補 / 死去 / 不明
（退任理由は公式資料で確認できる場合のみ登録する）

吉本 靖氏については、
- 現職議員一覧には含めない
- 過去の一般質問・会議録には表示する
- 当時の会期における議員活動として集計する
- 現在の現職議員比較には含めない
という既存方針を維持する。

過去の議員についても、同姓同名や氏名表記の揺れに対応するため、氏名そのものを
IDに使用しない。

### 議員の在籍履歴

人物情報と在籍期間を分離する。

```
memberTerms
- id
- memberId
- electionDate
- termStart
- termEnd
- termNumber
- status
- factionId
- constituency
- sourceUrls
```

会派、委員会、役職は途中で変更される可能性があるため、履歴として管理する。

```
memberAffiliationHistory
- memberId
- affiliationType
- affiliationId
- role
- startDate
- endDate
- sourceUrl
```

affiliationType例：faction / party / committee / councilRole

これにより、会期時点の所属会派・委員会・役職を表示できるようにする。

### 歴代市長

過去の延岡市長を、公式資料で確認できる範囲から登録する。

```
mayors
- id
- slug
- name
- nameKana
- termStart
- termEnd
- termNumber
- electionDate
- status
- profile
- manifestoSummary
- sourceUrls
- lastVerifiedAt
```

複数期務めた市長については、人物情報と任期情報を分離する。

```
mayorTerms
- id
- mayorId
- termStart
- termEnd
- termNumber
- electionDate
- electionType
- sourceUrls
```

表示できる内容：氏名 / 任期 / 就任回数 / 選挙年 / 就任当時の人口 /
就任当時の予算規模 / 任期中の市債残高 / 任期中の基金残高 / 任期中の主要事業 /
任期中の重要条例・計画 / 公式に確認できる政策・公約 / 後任・前任市長

市長の評価点や主観的な優劣判定は行わない。

### 過去データの取得元

次の一次情報を優先して調査する。

延岡市公式サイト / 延岡市議会公式サイト / 延岡市議会会議録 / 市勢要覧 /
市政概要 / 選挙管理委員会の選挙結果 / 市議会議員名簿 / 市議会だより / 予算書 /
決算書 / 決算審査意見書 / 財政状況資料集 / 財政健全化判断比率 /
地方公共団体の給与・定員管理資料 / 統計書 / 総合計画 / 市長施政方針 /
市長選挙公報 / 国または宮崎県が公開している公式統計

二次情報は、一次情報の所在確認のためだけに利用し、ポータルへ登録する数値や
事実は原則として一次情報で確認する。取得元URL、資料名、対象年度、該当ページを
保存する。

### 財政データ

財政データは年度単位で正規化する。

```
fiscalYears
- fiscalYear
- mayorId
- mayorTermId
- population
- households
- generalAccountInitialBudget
- generalAccountFinalBudget
- generalAccountSettlement
- totalRevenue
- totalExpenditure
- localTaxRevenue
- localAllocationTax
- nationalSubsidies
- prefecturalSubsidies
- municipalBondIssuance
- municipalBondBalance
- generalAccountBondBalance
- allAccountBondBalance
- fundBalance
- fiscalAdjustmentFund
- debtServiceRatio
- realDebtServiceRatio
- futureBurdenRatio
- currentAccountRatio
- financialStrengthIndex
- sourceUrls
- notes
- verifiedAt
```

単位を統一する：金額は円を内部値として保存、表示は億円・万円等へ変換、比率は
パーセント、人口は人、年度は会計年度。元資料が千円単位の場合は単位変換を明示して
正確に保存する。

「市債残高」については、次を混同しない。
- 一般会計の市債残高
- 普通会計の地方債残高
- 特別会計を含む残高
- 企業会計を含む全会計残高
- 一人当たり市債残高

元資料の定義を保存し、定義が異なる数値同士を同一グラフで直接比較しない。

### 予算規模の比較

最低限、次を年度別に表示する：一般会計当初予算 / 一般会計補正後予算 /
一般会計決算 / 特別会計予算 / 企業会計予算 / 全会計合計 /
市民一人当たりの一般会計予算 / 前年度比 / 5年前比 / 10年前比

予算と決算は別の数値として扱う。「予算が増えた＝自由に使えるお金が増えた」等の
誤解を招かないよう、人口、物価、国庫支出金、大型事業等の影響があることを注記する。

### 市債・基金の推移

年度別グラフを追加する。

市債：市債発行額 / 年度末市債残高 / 市民一人当たり市債残高 / 前年度からの増減 /
市長任期別の推移

基金：基金総額 / 財政調整基金 / 減債基金 / その他特定目的基金 /
市民一人当たり基金残高 / 前年度からの増減 / 市長任期別の推移

グラフ上で市長の任期が分かるようにする。ただし、市債の増減を市長個人だけの
成果・責任であるかのように表現しない。

### 政策データ

市長・議員の政策を比較できるようにする。

政策テーマ例：子育て / 教育 / 福祉 / 医療 / 防災 / 消防 / 高齢者施策 /
障がい福祉 / 産業振興 / 商工業 / 農林水産業 / 観光 / 雇用 / 移住・定住 /
人口減少 / 公共交通 / 道路・インフラ / 上下水道 / 環境 / 脱炭素 / デジタル化 /
行財政改革 / 市役所改革 / 地域コミュニティ / スポーツ / 文化 / 市街地活性化

```
policies
- id
- ownerType
- ownerId
- title
- summary
- categoryIds
- announcedDate
- sourceType
- sourceUrl
- sourceDocument
- status
- relatedFiscalYears
- relatedProjects
- lastVerifiedAt
```

ownerType：mayor / member / faction / city

sourceType：electionManifesto / policyDocument / councilQuestion /
mayorPolicySpeech / budgetDocument / comprehensivePlan / officialStatement

### 政策比較機能

政策比較ページを追加する。

比較対象：市長と過去の市長 / 議員と議員 / 現職議員と過去の議員 / 会派と会派 /
年度と年度 / 市長任期と市長任期

比較項目：公式に掲げた政策テーマ / 一般質問で扱ったテーマ / 質問回数 /
関連予算 / 関連事業 / 関連条例 / 進捗状況 / 出典 / 対象期間

政策比較では、「同じ政策」「類似政策」「異なる政策」を機械的に断定しない。
テーマ分類は事実検索を補助するものとし、政治的評価や優劣判定を行わない。

AIで政策を分類・要約する場合は、
- 原文を必ず保存する
- AI分類と明示する
- 原文リンクを表示する
- 人による修正が可能な構造にする
- AI分類を公式見解として表示しない
という条件にする。

### 政策の進捗状況

政策の状態は、公式資料に基づく場合のみ次のように管理する：
proposed（提案・公約） / planned（計画掲載） / budgeted（予算計上） /
started（事業開始） / ongoing（継続中） / completed（完了） /
changed（内容変更） / suspended（停止） / notVerified（確認できず）

「達成」「未達成」は、市が公式に進捗評価を公表している場合を除き、独自判断で
付けない。政策の進捗を表示するときは、根拠となる予算書、決算書、事業評価、
施政方針等を併記する。

### 比較ページ

次の比較ページを段階的に追加する。

1. 歴代市長一覧
2. 市長任期比較
3. 現職・元議員一覧
4. 議員在籍履歴
5. 議員政策比較
6. 市長政策比較
7. 年度別財政比較
8. 市債残高推移
9. 基金残高推移
10. 予算・決算規模推移
11. 人口と財政の比較
12. 市長任期別財政推移
13. テーマ別一般質問推移
14. 政策テーマ別の予算推移

URL例：/mayors, /mayors/[slug], /mayors/compare, /members/former, /members/history,
/members/compare, /policies, /policies/compare, /finance, /finance/debt,
/finance/funds, /finance/budget, /finance/compare

既存ルーティング規則に合わせて調整する。

### 比較画面の条件

比較対象を2件から最大4件まで選べるようにする。

比較対象例：市長2～4名 / 議員2～4名 / 年度2～4年度 / 市長任期2～4期間

表示項目：同じ定義・期間のデータのみ横並びで比較 / 単位を統一 / 出典を表示 /
データがない項目は「資料未確認」 / 0と未確認を区別 / 元資料へ移動できるリンクを
表示 / スマートフォンでも見やすい表示 / 表だけでなくグラフでも確認可能 /
グラフには数値表または代替テキストを付ける

比較結果を点数化したり、勝者・敗者を表示したりしない。

### 年代・任期フィルター

次の条件で絞り込めるようにする：年度 / 市長任期 / 市議会議員任期 / 会期 /
現職・元職 / 会派 / 委員会 / 政策テーマ / 資料種別 / データ公開状況

過去会期のデータは、その当時の議員・市長・会派・委員会構成に基づいて表示する。
現在の所属を過去会期へ遡って適用しない。

### データ品質

各データに次を保持する：sourceUrl / sourceTitle / sourceOrganization /
sourcePublishedDate / sourceUpdatedDate / accessedAt / pageNumber /
extractionMethod / verificationStatus / notes

verificationStatus：verified / partiallyVerified / needsReview / sourceUnavailable

数値の0と未取得を分けるため、未取得値を0で保存しない。未取得はnull等で管理する。

PDFから取得した数値は、資料名 / 年度 / 表の名称 / ページ番号 / 単位 を保存する。

### 自動巡回への追加

既存の5日ごとの自動巡回システムへ、次の資料の更新確認も段階的に追加する。

予算書 / 補正予算書 / 決算書 / 決算審査意見書 / 財政状況資料集 /
財政健全化判断比率 / 統計書 / 市勢要覧 / 総合計画 / 市長施政方針 /
市長政策・公約関連資料 / 議員名簿 / 会派・委員会構成 / 選挙結果

5日ごとの巡回では新着・変更検出を中心にし、大量の過去資料取得は別の
バックフィル処理として実行する。通常巡回と過去資料収集を分離する。

- regular-sync：5日ごとの更新確認
- historical-backfill：過去資料の段階的取得（手動実行を基本とし、公式サーバーへ
  過度な負荷をかけない）

最初の成果物：

設計段階では大量の過去データ取得や画面実装を開始しない。設計文書、必要最低限の

一度報告する。

### 禁止事項

- 過去議員や市長の在職期間を推測しない
- 出典のない政策を登録しない
- 市債と予算を混同しない
- 予算と決算を混同しない
- 異なる定義の財政数値を直接比較しない
- 未取得値を0として登録しない
- 政策の達成・未達成を独自判定しない
- 市長や議員を独自採点しない
- 政治的な推薦・批判を行わない
- 現職情報を過去の会期へ遡って適用しない
- AI生成文を公式資料として扱わない
- 本番ブランチへ直接pushしない
- デプロイしない

## 次セッションでの着手順序

1. 本ファイルと `docs/session-handoff.md` を読む
2. `docs/session-handoff.md`記載の未完了会期（あれば）を先に完了させる
3. 上記が完了していれば、本ファイルの「フェーズ1：最初に実施すること」に従い、
   調査・設計のみを行い `docs/historical-civic-data-plan.md` を新規作成する
4. 実装（データ追加・画面追加）はフェーズ2以降とし、ユーザーの明示的な進行指示を
   待ってから着手する
