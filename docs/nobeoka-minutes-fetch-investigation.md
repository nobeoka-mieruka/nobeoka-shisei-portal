# 延岡市議会「会議録検索システム」本文取得の実証結果（2026年8月）

以前の判断（「会議録本文は取得できない」）を見直した記録。ユーザーがブラウザで実際に本文を確認し、
`SpkChoice3.exe` のURLを提示してくれたことをきっかけに、Node.jsからの取得を再検証したところ、
**本文取得は可能であることが実際のHTTPレスポンスで確認できた。**

---

## 1. 結論（サマリ）

- `https://www.kensakusystem.jp/nobeoka/` は、CookieなしのシンプルなGET/POSTで会議録本文を返す。
- 全ページ Shift_JIS。Node標準の `TextDecoder("shift_jis")` で正しくデコードできる（追加ライブラリ不要）。
  ただしURLエンコード（Shift_JISバイトのパーセントエンコード）を組み立てる側には `iconv-lite`
  （軽量・依存なし）を追加した。
- 発言は「会議日ごと・発言順・発言者ラベル付き」で列挙でき（`r_Speakers.exe`）、各発言セグメントの
  本文だけを個別取得できる（`GetText3.exe`）。**発言順序が保持されるため、質問と答弁を機械的に
  対応付けられる。**
- 議員名（例: "前田遼君"）は `members.json` の氏名（"前田 遼"、全角スペース区切り）と、敬称・空白の
  正規化で突き合わせられることを確認した。

## 2. 検証したURLと結果

| # | エンドポイント | 目的 | 結果 |
|---|---|---|---|
| 1 | `SpkChoice3.exe?Code/fileName/発言者ラベル(SJISエンコード)` | 指定議員の指定会議日の発言をすべて取得 | HTTP 200、Shift_JIS、41,539バイト、文字化けなし |
| 2 | `See.exe`（POST, treedepth=年） | 年の一覧取得 | 未使用（2階層目のみ検証） |
| 3 | `See.exe`（POST, treedepth="令和 8年 第24回定例会 "） | 会期内の本会議日一覧（fileName）取得 | HTTP 200、6日分の`fileName`（R080216A〜R080319A）を取得 |
| 4 | `ResultFrame.exe?Code&fileName&startPos=0` | 本会議日ページ（フレームセット） | HTTP 200、正確な会議名を`<TITLE>`から取得できる |
| 5 | `r_Speakers.exe?Code/fileName/...` | その本会議日の発言順一覧（発言者・開始位置） | HTTP 200、158件の発言セグメントを発言順で取得（2/25分） |
| 6 | `GetText3.exe?Code/fileName/pos/10/1//0/0` | 発言セグメント1件の本文 | HTTP 200、対象議員の発言だけが返る（他発言者の混入なし） |

いずれもCookie送信なしで成功。`robots.txt`は存在しない（404）が、トップページに
`<meta name="robots" content="follow,index">` があり、明示的なクロール禁止は確認されなかった。

## 3. 文字コード

- HTTPヘッダ: `Content-Type: text/html; charset=shift-jis`
- HTML内: `<META http-equiv="Content-Type" content="text/html; charset=Shift_JIS">`
- Node標準の `new TextDecoder("shift_jis")` で正しくデコードできた（`市長（三浦久知君）` 等、
  文字化けなし）。エンコード側（URLに日本語を含める場合）は `iconv-lite` の `encode(str, "Shift_JIS")`
  を使用した。

## 4. HTML構造と本文抽出

- `GetText3.exe`のレスポンス：`<FONT class="TEXT2">`直下にプレーンテキスト＋`<BR>`改行。
- `SpkChoice3.exe`のレスポンス：`<BODY>`直下に「開催日：」「会議名：」のメタ情報に続けて、
  `○発言者　　本文`の形式でテキスト＋`<BR>`改行。
- どちらも`<SCRIPT>`・`<STYLE>`は本文と分離されており、単純な正規表現で安全に除去できる。
- 抽出ロジックは `scripts/lib/minutes-source.mjs` の `parseSegmentTextHtml()` に実装した。

## 5. URL構造の解析

`SpkChoice3.exe?48o046ot0cia1xvtw7/R080216A/%8E%73%92%B7%81%69%8E%4F%89%59%8B%76%92%6D%8C%4E%81%6A`

| セグメント | 値 | 意味 |
|---|---|---|
| 1 | `48o046ot0cia1xvtw7` | サイト（延岡市議会）固有の"Code"。トップページのメニューリンクにも同じ値が
埋め込まれており、**リクエストごとに変わるセッション値ではなく、この会議録検索システム
インスタンス固有の固定値**であることを確認した（複数回・複数エンドポイントで同一値が
使えた）。 |
| 2 | `R080216A` | 会議ファイル名。`R` + 元号年2桁（令和8年→`08`）+ 月2桁 + 日2桁 + 会議区分の英字
（本会議は`A`）。`See.exe`の木構造ナビゲーションから機械的に取得できる（後述）。 |
| 3 | パーセントエンコードされたShift_JISバイト列 | 発言者の表示ラベルそのもの（例:
"市長（三浦久知君）"）。**推測で組み立てず、`r_Speakers.exe`が返す発言者一覧のラベルを
そのまま使うこと**（表記ゆれ・敬称の有無がページごとに一定でない可能性があるため）。 |

`GetText3.exe`・`r_Speakers.exe`は `Code/fileName/位置引数.../` という共通のパス形式で、
`SpkChoice3.exe`とは異なりセッション状態を必要としない（同じURLを新しいプロセスから
実行しても同じ結果が返ることを確認済み）。

## 6. 発言者一覧の取得

`See.exe`への2段階のPOST（`treedepth`に「年」→「会期名」を順に指定）で、本会議日ごとの
`fileName`一覧が取得できる。`scripts/lib/minutes-source.mjs`の`listMeetingDays()`に実装し、
実際に令和8年第24回定例会の6会議日（R080216A〜R080319A）を取得できることを確認した。

各会議日の発言者一覧は`r_Speakers.exe`が返す（`listSpeakerSegments()`）。手作業でURLを
組み立てるのではなく、この一覧から発言者ラベルと開始位置（`pos`）を機械的に取得する方式を
採用した（依頼のとおり、推測でURLを構築しない）。

## 7. 議員1名分の試験（前田遼議員、令和8年3月定例会）

`令和 8年 第24回定例会（第2号 2月25日）`の発言者一覧（158セグメント）の中から、
`members.json`の"前田 遼"（`m21`）に一致する"前田遼君"を検出した。

- 発言位置`pos=15368`：前田議員本人の代表質問（本文6,369文字）。冒頭に
  「友愛クラブの前田　遼です」と名乗っており、本人の発言であることが本文からも確認できる。
- 直後の`pos=27292`：市長の答弁（本文1,890文字）。冒頭が「ただいまの前田　遼議員の御質問に
  お答えいたします」であり、前田議員への答弁であることが本文から確認できる。
- 他の発言者（議長の進行発言等）は、`r_Speakers.exe`の一覧上で別セグメントとして明確に
  分離されており、`GetText3.exe`で取得したテキストへの混入は確認されなかった。
- なお、この日は「代表質問」であり、本人の発言は`一般質問`ではなく`代表質問`に分類した
  （本文内に「今回の代表質問は」「それでは、代表質問に移ります」と明記されている）。
- 前田議員の質問は多数の項目（予算・アプリ・保育所申請・パブリックコメント・廃棄物処理計画・
  移住定住・ふるさと納税・中小企業支援・投票環境・学校体育館空調など）にわたるが、市長の
  最初の答弁セグメントで直接回答しているのは「予算編成（シーリング・基金）」「パブリック
  コメント」「ふるさと納税」の3項目のみだった（残りは他の部局長がこの後のセグメントで
  回答している）。**答弁本文で確認できた範囲のみを要約対象とし、確認していない項目は
  含めていない。**

## 8. 質問と答弁の対応付け（会議全体の発言順序）

`r_Speakers.exe`が返す発言リストは、実際の発言順（No.1, No.2, ...）どおりであることを
確認した。前田議員の発言直後に市長の答弁が続き、その後も
`前田遼君 → 総務部長 → 前田遼君 → 総務部長 → 前田遼君 → 企画部長 → ...`という、
一問一答形式の応酬がそのままの順序で列挙されていた。

これにより、**発言者別に本文を集めるだけでなく、会議全体の発言順序を保持した状態で
質問と答弁を機械的に対応付けられる**ことが確認できた（依頼で懸念されていた「発言者別本文だけを
時系列と誤認する」リスクは、`r_Speakers.exe`の順序をそのまま使う限り発生しない）。

## 9. AI要約の試験

前田議員の代表質問のうち、市長が直接答弁した3項目（予算編成のシーリング・基金／
パブリックコメント／ふるさと納税）について、要約候補を1件作成し
`src/data/councilSpeechSummaries.json`（`memberId: "m21"`）へ登録した。

- `summaryStatus: "pending"`、`isPublished: false`（自動的に`verified`へは変更していない）
- 要約には、本文に記載された事実（数値・方針・実施予定等）のみを用い、評価・推測・
  感情的表現は加えていない
- `npm run speeches:list-pending` で正しく「確認待ち1件」として表示されることを確認した
- 承認前チェック（`npm run speeches:approve -- --id=... --dry-run`）もすべてOKと判定された
  （実際の承認は行っていない。人による公式会議録との照合が必要なため）
- 一般公開ページ（議員詳細ページ）では、`isPublished: false`のため表示されず、
  引き続き「会議録本文未取得」の案内が表示されることを確認した（`dist/members/m21/index.html`を
  ビルド後に確認済み）

## 10. アクセス負荷への配慮

- `scripts/lib/minutes-source.mjs`の`throttle()`で、リクエスト間隔を最低2秒に制限した。
- `scripts/fetch-nobeoka-speaker-minutes.mjs`は、出力ファイルが既に存在する場合は再取得しない
  （`--force`で明示的に上書きしない限りスキップする）。
- 失敗時の再試行は最大2回まで（無限リトライしない）。
- User-Agentに連絡先ページのURLを含めて明示した。
- 今回の試験で行った実際のHTTPリクエストは合計10回未満（年一覧・会期一覧・本会議日一覧・
  発言者一覧・本文取得3件・CLIでの再取得防止確認）。

## 12. 残っている課題

- `See.exe`の1階層目（年の選択）の自動化は未実装（今回は2階層目のtreedepthを直接指定した）。
  全会期を横断的に取得する場合は、まず年一覧を自動走査する処理が必要。
- キーワード検索（`Search2.exe`）は未調査（議員名や日付が事前に分かっている場合は
  `See.exe`の木構造だけで到達できるため、優先度は低いと判断した）。
- 議員名の表記ゆれ（"前田遼君" と "前田 遼"、敬称の有無、旧字体等）を機械的に正規化する
  ルールは、他の議員での検証が必要。
- 答弁が複数の部局にまたがる場合（今回の前田議員の代表質問のように）、どこまでを
  「対応する答弁」として1つの質問項目に含めるかの判断ロジックは、今回は人手（今回はAI＝筆者）
  による個別確認で行った。自動化する場合は、質問文中の項目区切り（見出し的な文）と
  答弁側の話題転換（「次に、」等の接続表現）を手がかりにする案が考えられるが、精度検証が必要。
- `fetchMinutesForSpeech()`を実際にsessionId/memberIdから会議・発言セグメントを解決する
  完全なパイプラインへ拡張する作業（`docs/council-speech-summary-pipeline.md`の【7】以降）。
- 大量取得時のCookie・レート制限方針の最終確認（今回の少数リクエストでは問題は出なかったが、
  全26会期・26議員規模でのアクセス量については、事前に議会事務局へ確認することが望ましい）。

## 13. 段階的展開（パイロット・2026年8月追記）

上記の実証結果を基に、いきなり全議員・全会期へ展開せず、次の範囲で試験公開まで進めた。

### 13.1 See.exeの年階層ナビゲーション自動化

「残っている課題」に挙げていた年階層（令和5年〜令和8年）の自動探索を実装した
（`scripts/lib/minutes-source.mjs`の`resolveYearTreedepth()` / `listSessionsForYear()`）。

- トップページ相当（`See.exe?Code=...`のGET）から、左サイドバーの年タブ一覧を解析する。
- 対象年が個別タブの場合（例: 令和8年）は直接その値を使う。
- 対象年がグループタブ（例: "令和 5年～令和 7年"）に含まれる場合は、そのグループの
  treedepth値で一度POSTし、再表示されるサイドバーから対象年の個別タブ値を取得する
  （2段階解決）。令和5年〜令和8年の範囲で実際に動作確認済み（`npm run minutes:discover -- --year=2025`
  と`--year=2026`の両方で正しい会期一覧を取得できた）。

### 13.2 議員名の正規化

`matchSpeakerToMember()`を実装し、以下の表記ゆれを実データで確認した／依頼の例で検証した。

- "前田遼君" → m21（実データで確認）
- "前田 遼君"／"前田 遼議員"／"○番（前田遼君）" → m21（依頼の例で検証、いずれも正しく一致）
- "宮田博徳君" → m24、"甲斐忠篤君" → m07、"山本珠美君" → m25（いずれも実データで確認）
- "議長（早瀨賢一君）"・"市長（三浦久知君）"は、氏名だけで自動確定せず、
  `classifySpeakerLabel()`が別種別（chair/mayor）として扱うため、議員としてはマッチしない
  （意図した動作）。
- 一致しない場合はundefinedを返し、`speaker-identification-pending`として扱う設計。
- 未対応：旧姓・異体字（髙/高、﨑/崎等）の表記ゆれ。実際に遭遇した時点で、個別の議員データに
  「別表記」を追加する形で拡張する想定。

### 13.4 アクセス制御バッチツール

`scripts/fetch-nobeoka-minutes-batch.mjs`（`npm run minutes:fetch -- --year=<年> --limit=<件数> [--dry-run]`）
を新設した。指定年の会期・本会議日を自動列挙し、議員発言セグメントとその直後の答弁セグメントを
特定して本文を取得する。要約の作成・`councilSpeechSummaries.json`への登録は行わない
（原文取得までを自動化し、要約は引き続き人（またはAI）による個別確認を要する設計）。

- 同時取得数は常に1
- リクエスト間隔は最低2秒（`scripts/lib/minutes-source.mjs`のthrottleを継承）
- `--limit`で取得件数の上限を指定（省略時10件）
- `--dry-run`で、本文取得前に対象一覧だけを確認できる
- 取得済み（出力ファイルが既存）のセグメントはスキップする（途中再開が可能）

`--year=2026 --limit=5 --dry-run`で実行し、対象5件（前田議員の質問・再質問とその答弁）が
正しく列挙されることを確認した。`--limit=1`（dry-runなし）で実際に1件取得できることも確認し、
再実行時に正しくスキップ（再取得しない）されることも確認した。

## 14. 利用条件の確認

- `robots.txt`は存在しない（404）。
- トップページに`<meta name="robots" content="follow,index">`があり、明示的なクロール拒否は
  設定されていない。
- 操作説明トップページ（`help/help_top.html`）を確認したが、利用規約・利用上の注意・
  自動取得禁止に関する記載は見当たらなかった（起動方法・閲覧方法・検索方法・印刷方法・
  ダウンロード方法へのリンクのみ）。
- サイト内で確認できた唯一の利用上の注記は、データの正確性に関するもの
  （「漢字表記については、汎用性を考慮し、JIS第2水準までの漢字を使用しています」）で、
  アクセス制限に関するものではない。
- **明示的な自動取得禁止は確認できなかったが、これは無制限な取得を許可する意味ではない。**
  今回はアクセス負荷を抑えた取得方式（2秒以上の間隔、少数件数、キャッシュ）を維持した。
  全26会期・26議員規模への本格展開の前に、延岡市議会事務局へ確認することを推奨する。
